# 公众号文章数据：提取规则与表格维护规则

本目录下这套东西解决一件事：**把公众号后台导出的单篇明细 .xls 变成一张可持续维护的分析表**。

| 文件 | 角色 |
|------|------|
| `../../raw/data/wechat/*.xls` | **唯一数据源**。后台导出的单篇明细，新数据丢这里就行 |
| `import_wechat_export.py` | **唯一入口**。解析 → 写入 → 重算透视表，一条命令 |
| `公众号文章数据分析表.xlsx` | **产物**。sheet1 `文章数据记录`（逐篇明细）+ sheet2 `方向×价值类型透视`（分组汇总） |
| `公众号文章数据分析模板.xlsx` | 母本。仅在分析表不存在时用于首次生成（原已丢失，2026-09-21 从 WPS 缓存找回） |

```bash
cd tools/wechat-data
python3.12 import_wechat_export.py     # 读 raw/data/wechat/ 下全部 .xls，增量并入分析表
```

---

## 一、导出文件的两种结构

后台导出有两种版本，**字段口径不同、列数不同**。脚本按表头定位、按列名取值，不认死行号。

| | 人数版 | 次数版 |
|---|---|---|
| 数据概况的头部指标 | `阅读(人)` `分享(人)` `在看(人)` `点赞(人)` `收藏(人)` `听全文（人）` `新增关注（人）` | `阅读(次)` `分享(次)` `在看(次)` `点赞(次)`（**无收藏**）`互动率` `阅读后关注（人）` |
| 阅读转化分区 | `送达人数` `公众号消息阅读人数` `首次分享人数` `总分享人数` `分享产生的阅读人数` | 同名但都以「次」计 |
| 趋势明细表头 | `日期 \| 传播渠道 \| 阅读人数 \| 分享人数` | `日期 \| 传播渠道 \| 阅读人数 \| 阅读次数 \| 分享人数 \| 分享次数` |
| 已知篇数 | 32 篇 | 6 篇 |

**两版都以趋势明细「全部」渠道行还原人数口径**：`阅读人数` 从趋势明细「全部」行求和得到，所以人数版没有「阅读(次)」也不影响。
次数版还多一列「阅读次数」，但表里没有对应的列（`阅读次数` 已删），只用它做交叉校验。

趋势明细按表头行（含 `日期` + `传播渠道` 的那一行）定位，其余分区按「分区标题 + 指标名」取值；分区标题为 `数据概况 / 阅读转化 / 阅读数据趋势明细 / 性别分布 / 年龄分布 / 地域分布`。指标名做归一化（中英文括号、空格都等价）。

## 二、逐列提取规则（sheet1 `文章数据记录`）

行范围：第 6~49 行（不够时脚本自动加长）。列共 **39 列，A~AM**、六层。列位置由脚本里的 `LAYERS` 定义：
每次运行按它重铺第 4 行分组横幅与第 5 行列名，表变宽/变窄自动跟随（多出来的旧列整列删掉），
**改口径只要改 `LAYERS`**，不用手工调表头。

| 列 | 字段 | 来源 / 算法 | 脚本行为 |
|---|---|---|---|
| A | 序号 | 按发布日期倒序重编 1..N | 自动，**每次重编** |
| B | 发布日期 | 趋势明细「全部」行的最早日期 | 自动（导出文件本身没有「发布日」字段） |
| C | 标题 | 导出文件第 1 行 B 列（**正文标题，不是文件名**） | 自动 |
| D | 字数 | —— | 人工 |
| E | 内容方向 | 分类规则（见第五节） | 仅空着时填 |
| F | 人群匹配度 | 三档阈值（见第六节） | 仅空着时填 |
| G | 核心价值类型 | 分类规则 | 仅空着时填 |
| H | 阅读人数 | 趋势明细「全部」行 `阅读人数` 合计 | 自动 |
| I | **目标人群阅读量** | `阅读人数 × 25-45岁读者占比`（对目标读者的触达，成绩单口径） | 自动 |
| J | 送达人数 | 阅读转化 / 送达人数 | 自动 |
| K | 公众号消息阅读人数 | 阅读转化 / `公众号消息阅读人数`（次数版为「次数」） | 自动 |
| L | 首次分享人数 | 阅读转化 / `首次分享人数`（次数版为「次数」） | 自动 |
| M | 订阅打开率 | 公式 `=K/J` | 公式 |
| N | 订阅分享率 | 公式 `=L/K` | 公式 |
| O | 完读率 | 数据概况 / 完读率 | 自动 |
| P | 平均停留时长 | 数据概况 / 平均停留时长(秒) | 自动 |
| Q | 微信收藏人数 | 数据概况 / `收藏(人)`（**仅人数版有**） | 有则写 |
| R | 收藏率 | 公式 `=Q/H` | 公式 |
| S | 点赞数 | `点赞(人)` 或 `点赞(次)` | 自动 |
| T | 在看数 | `在看(人)` 或 `在看(次)` | 自动 |
| U | 分享人数 | 趋势明细「全部」行 `分享人数` 合计 | 自动 |
| V | 分享率 | 公式 `=U/H` | 公式 |
| W | 分享产生的阅读人数 | 阅读转化 / `分享产生的阅读人数`（次数版为「次数」） | 自动 |
| X | 分享扩散系数 | 公式 `=W/U`（每个分享者带来多少阅读，倍数） | 公式 |
| Y | 读后关注人数 | `新增关注（人）` 或 `阅读后关注（人）` | 自动 |
| Z | 女性读者占比 | 性别分布 / 女 | 有则写 |
| AA | 25-45岁读者占比 | 年龄分布 / 26-35岁 + 36-45岁（后台不直接给，需相加） | 有则写 |
| AB | **46岁以上占比** | 年龄分布 / 46-55岁 + 56-65岁 + 65岁以上 | 有则写 |
| AC | 目标人群匹配度 | 公式（三档判定，看 Z/AA） | 公式 |
| AD | 单篇涨粉数 | 同 Y（同一后台指标的两种叫法） | 自动 |
| AE | 涨粉转化率 | 公式 `=AD/H` | 公式 |
| AF~AM | 阅读渠道构成：公众号消息/公众号主页/聊天会话/朋友圈/朋友在看/推荐/搜一搜/其他 占比 | 趋势明细里该渠道各行 `阅读人数` 之和 ÷ 阅读人数 | 自动（该渠道没流量为 0%） |

**两个目标人群口径的列**（`I 目标人群阅读量`、`AB 46岁以上占比`）解决的是"写给谁"的问题：
前者是成绩单（流量里有多少落到了 25-45 岁读者），后者是**反向护栏**（越低越好）。
它们取代了「用阅读量排优先级」的旧做法——某方向阅读量大不等于触达了目标读者。

**色阶条件格式**：
- 正向指标（越高越好）红→黄→绿：`H 阅读人数`（10/50/90 分位数）、`I 目标人群阅读量`（分位数）、
  `M 订阅打开率`、`O 完读率`、`V 分享率`、`Z 女性读者占比`、`AA 25-45岁占比`、`AE 涨粉转化率`。
- **反向指标**（越低越好）**绿→黄→红**：`AB 46岁以上占比`——老龄化是当前最该压下去的数
  （9 月已到 67%）。
- **第六层按行染色**：每行 8 个渠道各一条色阶（`AF{行}:AM{行}`，共 44 条），行内比较，
  单色浅→深蓝（渠道占比高不代表好，红绿会误导）。

**公式列**（M/N/R/V/X/AC/AE）由脚本生成：数值型公式来自 `FORMULA_INPUTS` 的「分子/分母列名」，
列位一变自动跟随（不写死字母），文本型（匹配度）单独写。公式都带空值与 0 值保护。

**公式的缓存值**：openpyxl 写出的公式没有缓存结果，WPS/Excel 重算前读不到数字——公式列会空白、
**色阶着不上色**。脚本保存后由 `inject_cached_results` 把算好的结果写进公式格的 `<v>`；
打开即见数字与颜色，公式本身仍是活的（`fullCalcOnLoad`）。

**取不到就不写**：某列在源文件里没有对应指标时，该行该列留空（人工列与判断列除外，它们从历史行继承）。纯人工列只有 `D 字数`。
**填写说明区**：第 50 行起 9 行（【填写说明】+ 六层说明 + 数据更新延迟 + 核心指标参考），样式由脚本显式指定。

## 三、口径陷阱（都是实际踩过的）

1. **打开率口径已更正**。原来的 `阅读人数 ÷ 送达人数` 对推荐流量文章会算出几千个百分点（全表均值 542%），已删。现在的 J 列「订阅打开率」用后台真实口径 `公众号消息阅读人数 ÷ 送达人数`（本批 38 篇在 0.3%~5% 之间）。
   - **次数版导出的副作用**：那 6 份导出没有人数口径，只能用「公众号消息阅读次数 / 首次分享次数 / 分享产生的阅读次数」，所以 L 订阅打开率、M 订阅分享率可能 >100%（脚本如实写入并在输出里告警）。
   - Y 列「分享扩散系数」是**倍数**（如 2.3 = 每个分享者带来 2.3 个阅读），不是百分比，格式 `0.00`。
   - 次数版的分母是「分享人数」（人），分子是「分享产生的阅读次数」（次）——**口径混用**，这 6 篇的系数偏高
     （例：旧口径 1.58 → 新口径 3.80）。人数版没有这个问题。
2. **渠道占比有去重差**。各渠道阅读人数之和可能大于「全部」行（同一人多次进入），所以单渠道占比理论上可能 >100%；
   脚本遇到这种情况会跳过该列并在输出里告警。第六层的各项占比之**和**也常见 100%~110%，属正常。
3. **分布的三种存法都要认**：`'69.42%'`（百分比字符串）、`0.6942`（小数）、`51`（**绝对人数**）都可能出现——
   人数版导出给百分比，次数版导出给人数（女 51 / 男 13）。脚本按**合计**判断：合计 >1.5 就归一化（除以合计），
   所以两种导出混在一张表里也能比。**踩过的坑**：早期版本把次数版的 `51` 当成 51%，导致那 6 篇的女性占比、
   25-45 岁占比、匹配度全错（应 79.7%）。
4. **年龄分档名两套**：人数版是 `46-55岁 / 56-65岁 / 65岁以上`，次数版是 `46-60岁 / 60岁以上`
   ——识别「46 岁以上」要把两套都算上。
5. **读者太少后台不生成用户画像**：X/Y 空 → 匹配度无法判定 → 该行在透视表里归到「（未填写）」分组。
6. **比例写入定 6 位小数**，否则 xlsx 的 15 位有效数字会在每次重跑时报出一堆假的「数据变化」。
7. **导出文件里没有的指标**：只有 `字数`（纯人工填）；`微信收藏人数` 仅人数版有。这些列留空是如实反映，不是漏填。

## 四、表格维护规则（增量语义）

跑一次脚本 = 增量并入，规则如下：

1. **新标题 → 追加一行**（按发布时间倒序插入到正确位置）。
2. **已有标题 → 只刷新数据列**（H/I/J/L/M/N/O/Q/S/T/U/W/X/Y/AA 及公式列），无变化则不报告。
3. **行永不删除**：data/ 里删掉某份导出，表里那一行仍然保留（输出里会标「保留（data/ 里已无这份导出）」）。
4. **人工列永不覆盖**：D 字数 / E 内容方向 / F 人群匹配度 / G 核心价值类型。手改过的值（含下拉改分类）重跑一定保留；**只有空着的单元格**才会被填默认值。想让某格按新数据重算，先把它清空再跑。
5. **行序与序号**：按发布日期倒序，序号重编 1..N（序号是显示顺序的产物，不要手改）。
6. **表结构自适应**：数据区固定 6~49 行；装不下时脚本自动加长 10 行，并把第 50~57 行的「填写说明」整块继续下移（合并格式与内容完整保留）。下拉验证范围（E/F/G）与公式列同步扩展。
7. **列结构整理**：模板原本把「涨粉转化率」的表头挂在 AB（整列无数据），公式却写在表外的 AC 列。脚本把公式收回 AB、补上 AB 表头，并**删掉多余的 AC 列**，横幅合并区收回到 AB（幂等，只做一次）。现在表就是 A~AB 28 列。
8. **同一篇导出多次**（文件名带 `(1)` 那种）按标题去重，保留指标更全的一份。
9. **一份解析失败就整体停下、不写文件**——避免写出半成品表。（这个保护是被一次事故逼出来的：早期版本在某份文件解析失败时仍然落盘，把数据区清空过。）

## 五、分类规则（E 内容方向 / G 核心价值类型）

三层，命中即停：

1. **`TITLE_RULES`（脚本顶部）**：逐篇过目后写死的结论，`(标题关键词, 内容方向, 核心价值类型)`。现有 38 篇都在这里，最可靠。
2. **关键词表 `DIRECTION_RULES` / `VALUE_RULES`**：给新文章兜底推断，按顺序先命中者优先。
3. **方向二级兜底 `VALUE_BY_DIRECTION`**：标题看不出价值取向时按方向推（育儿育己→情绪共鸣、植物美学→审美滋养、追剧观影/深度思考→认知启发、生活感悟→情绪共鸣）。再不然才用 `纯粹记录`。

**新文章要固化分类**：在 `TITLE_RULES` 加一行即可，例如
`("阳台上的月季", "植物美学", "审美滋养"),`

**已知误命中坑**（写关键词时避开）：裸词 `花` 会撞「花**钱**」「花**魁**」；`如何`/`怎么` 会撞「我们究竟该**如何**感受美」（那是审美滋养，不是实用方法）；`剧` 会撞「剧烈」。所以植物词写成 `插花/花香/花园/绿植/菊花/开花` 这类组合词，影视词写成 `电影/剧集/重看/小评` 这类。

## 六、人群匹配度（F 列与 Z 列）

模板只定义了「女性≥60% 且 25-45岁≥50% = 高匹配」，中/低两档由本套规则补齐：

| 条件 | 档位 |
|---|---|
| 两项都达标 | 高匹配 |
| 恰好一项达标 | 中匹配 |
| 都不达标 | 低匹配 |

F 列（下拉，可手改）与 Z 列（公式）**用同一套阈值**，不会再出现两列说法不一致。

## 七、两张汇总表：结论框架 v2

模板原来只有一张「方向×价值类型透视」。**v2 把「先分层、再比较」写进框架**——因为推荐流量是冷流量，
完读率与分享率天然低于私域（实测算法型完读中位 20.7%、私域型 46.9%，差 2.3 倍），拿一条绝对线同时管两类文章，
结论必然反向。旧版就把「阅读 38596 的算法爆文」判成了「减少或优化」。

### 7.1 流量结构分层（一切比较的前提）

按第六层的 `推荐占比` 分三层：**算法型 ≥70% / 混合型 30~70% / 私域型 ≤30%**。

| 流量层 | 篇数 | 中位阅读 | 订阅打开率 | 完读率 | 分享率 | 扩散系数 | 涨粉转化 | 25-45岁 | 占全表阅读量 |
|---|---|---|---|---|---|---|---|---|---|
| 算法型 | 13 | 378 | 2.42% | 20.7% | 3.1% | 2.00 | 0.5% | 25.2% | **96%** |
| 混合型 | 11 | 119 | 2.49% | 39.6% | 7.7% | 4.29 | 0.5% | 58.8% | 2% |
| 私域型 | 14 | 48 | 3.37% | 46.9% | 13.8% | 3.68 | 0.9% | 57.1% | 1% |

读法：**流量几乎全来自算法型（96%）**，但私域型的完读/分享高得多——两者回答的不是同一个问题，
所以不能互相当基准。

### 7.2 「方向×价值类型透视」的结论（每行三段）

格式：`【定位】流量结构＋轨道＋最弱维度 ／【诊断】三个指标与同层水平的对比 ／【动作】按轨道×短板给`

- **定位**：`{算法型/混合型/私域型}为主 n/N 篇·{增长轨/基本盘轨}` ＋ 最弱的那个维度（相对同层不足 0.90 倍才算短板，
  否则写「各维度不低于同层」）。轨道＝算法型走**增长轨**（盯冷流量承接与关注转化），其余走**基本盘轨**（盯打开、分享、扩散）。
- **诊断**：完读率、分享率、涨粉转化率（扩散系数为短板时也列出）＋「同层 x%」的对照值。同层期望 = 组内各篇
  按其所属层的基准加权平均，所以混合层的组也能公平比较。
- **动作**：由 `ACTIONS[(轨道, 短板)]` 给出（10 条：增长轨/基本盘轨 × 内容力/传播力/扩散力/沉淀力/无短板）。
  四个维度＝**内容力**（完读率）、**传播力**（分享率）、**扩散力**（分享扩散系数）、**沉淀力**（涨粉转化率）；
  都不低于同层却人群偏时，给「换切角」而不是改内容的动作。

### 7.3 「流量结构透视」（另一张 sheet）

三层各自的中位表现 ＋ 层内结论（`【定位】角色＋占全表阅读量 ／【诊断】中位阅读/完读/分享/扩散/涨粉 ／【动作】该层怎么用`）。
与 7.2 那张回答的不是同一个问题：**7.2 看内容组合，7.3 看流量结构值不值得投入**。
表由脚本自动创建/更新（`build_regime_sheet`），样式沿用 7.2 的表头配色。

### 7.4 其他口径

- 指标用**中位数**（均值 1436 vs 中位 116，均值被 38596 那篇拖着）；涨粉转化率用**均值**（中位数常为 0，没法比）。
- 某篇缺该指标就从统计里剔除，不当 0；“无画像”的组单独给「先攒阅读量」的动作。
- 渠道占比列**按行染色**（浅→深蓝，行内比主力渠道），关键质量列**整列染色**（红→黄→绿）。

## 八、日常操作

**加新数据（推荐）**：把后台导出的 .xls 丢进 `raw/data/wechat/`，然后对 AI 说「帮我更新公众号文章数据」（已配 skill，会自动跑完整流程）。

**手动跑**：

## 九、排障

| 症状 | 原因 / 处理 |
|---|---|
| `解析失败: …` 并整体停下 | 后台改了导出结构。看报错里缺哪个指标/表头，再改脚本的取值逻辑；**不要手工绕过或直接把数值塞进表** |
| `未解析到趋势明细` | 该导出没有趋势表头（`日期` + `传播渠道`）。先人工打开确认是不是新版式 |
| 表里少了某列数据 | 对照第二节「取不到就不写」：`微信收藏人数` 只有人数版导出有、`AB/AC 女性与25-45岁占比` 在读者太少时后台不生成画像（该行匹配度也就无法判定），属正常留空 |
| 条件格式的色阶不显示 | ① 公式列没有缓存值（老版本问题，已由 `inject_cached_results` 修好）；② WPS 里打开的是改动前的旧副本——**完全关闭该文件再重新打开**；③ 空值/分母无定义的行本来就不上色 |
| 订阅打开率 >100% | 次数版导出按「次」算所致，见第三节第 1 条；人数版不该出现 |
| 序号乱了 / 分类被改了 | 序号每次重编属预期；分类只在空着时才填，手改的不会被覆盖——若被改了说明该格之前是空的 |
| 提示模板文件不存在 | 母本 `公众号文章数据分析模板.xlsx` 不在目录里。分析表已存在时不影响使用；但一旦分析表也丢失就无法重建。2026-09-21 已从 WPS 缓存副本找回并入库 |
| 脚本拒绝运行：「检测到锁文件 .~…」 | 表正被 WPS/Excel 打开。关闭它再跑；**不要为了绕过而删除锁文件后边用边改**（一保存就把脚本写的内容覆盖回去） |

## 十、不要做的事

- 不要手改 A 列序号（每次重编）。
- 不要指望从 `raw/data/wechat/` 删文件能让表里那行消失（行永不删除，这是刻意的）。
- 不要在 WPS/Excel 打开分析表时跑脚本。
- 不要手工往表里插行/删行来"整理"——行位置由脚本按日期倒序排，插进去会被下一次运行挪走。
- 不要用 `git add .` 提交（仓库既有规则）；`raw/data/wechat/` 下的 42 份导出是唯一原始来源，已纳入版本控制，删除前先确认。
