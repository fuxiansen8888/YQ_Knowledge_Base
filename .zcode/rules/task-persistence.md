# 长任务持久化与防漂移

## 一、何时启用

满足以下**任一**条件时，本规则生效：

- 预估步骤 ≥ 5 步（跨多文件、多阶段）
- 涉及研究 + 实现两个阶段
- 用户明确要求"做个计划"

单文件修改、快速查询、一问一答 → 跳过本规则。

---

## 二、Plan 文件

路径：`.claude/plans/<slug>.md`（slug 取任务关键词，如 `stitch-retro-118-021`）

```markdown
# <任务标题>

> 状态: 待确认 | 已批准 | 执行中 | 完成

## 目标（一句话）
<完成后重读这行，确认没有偏离>

## 方案权衡
| 方案 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| A: ... | ... | ... | ✅ 采用 / ❌ 否决 |
| B: ... | ... | ... | ✅ 采用 / ❌ 否决 |

## 阶段
- [ ] Phase 1: ...
- [ ] Phase 2: ...
- [ ] Phase 3: ...

## 发现与中间结论
<每完成一个 phase 追加要点>

## 错误记录
<失败的方案 + 原因，防止重试>
```

---

## 三、批注协议

用户可直接编辑 plan 文件添加批注，格式：

```markdown
> [批注] 这个假设不对，实际上 XXX
> [否决] 方案 B 不行，因为 YYY
> [补充] 还需要考虑 ZZZ
```

**Claude 的响应规则**：
1. 重读 plan 文件时，扫描所有 `> [批注]`/`> [否决]`/`> [补充]` 标记
2. 针对每条批注修订对应段落，修订后在批注下方追加 `> [已响应]` 标记
3. 修订完成后向用户简报改动点

**批注轮次上限**：默认最多 3 轮批注循环。第 3 轮结束后，若用户无新批注，自动视为已批准进入执行。用户可随时说"没问题了"提前结束循环。

---

## 四、状态机

Plan 文件的 `状态` 字段控制 Claude 的行为：

| 状态 | Claude 可以做什么 |
|------|-----------------|
| **待确认** | 只能修订 plan（响应批注、补充细节），**禁止执行实施动作** |
| **已批准** | 可以执行。纯文件操作一口气完成不逐步问；涉及 SQL 执行/git push 等不可逆操作仍逐步确认 |
| **执行中** | 正在实施，按阶段推进 |
| **完成** | 勾选所有 checkbox + 追加完成日期 |

**状态转换**：
- `待确认` → `已批准`：用户明确说"可以了"/"没问题"/"执行吧"，或 3 轮批注无新增
- `已批准` → `执行中`：Claude 开始第一个实施动作时自动转换
- `执行中` → `完成`：所有 Phase checkbox 勾选

---

## 五、Goal Drift 防护

每完成一个 Phase（或连续 ≥8 次工具调用后），**重读 plan 文件的"目标"行**，自检：

1. 当前动作是否还在服务目标？
2. 是否产生了目标外的副作用？

偏离时立即停下，向用户说明偏移方向。

---

## 六、错误不重复

方案/路径失败时：

1. **立即记录到 plan 文件的"错误记录"区**：失败方案 + 具体原因
2. 下次尝试前**先检查错误记录**，禁止重试已证明失败的路径
3. 跨会话有价值的错误额外写入 Memory（feedback 类型）

---

## 七、/clear 后恢复

会话被清理或上下文压缩后，如果 `.claude/plans/` 下存在未完成的 plan 文件（状态非"完成"）：

1. 读取该 plan 文件（含批注和错误记录）
2. 向用户确认："检测到未完成的计划 [标题]，当前状态 [X]，是否继续？"
3. 用户确认后从上次状态继续
