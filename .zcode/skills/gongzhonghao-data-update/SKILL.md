# 公众号文章数据更新

一句话：**`raw/data/wechat/` 是投递口，一条命令把新数据增量并入分析表**。

详细规则见 `tools/wechat-data/数据提取与维护规则.md`（字段提取规则、口径陷阱、分类规则、透视表算法），执行前若不确定细节先读它。

## 触发场景

- 「帮我更新公众号文章数据」「更新公众号数据」「公众号数据」
- 「我把新导出的数据放进去了」「新文章数据加一下」
- 「公众号文章数据分析表 / 方向×价值类型透视 怎么样」

## 执行流程

### 步骤 1：预检（别跳，跳了可能白干）

```bash
cd tools/wechat-data
ls -a | grep '^\.~'                       # 有 .~公众号文章数据分析表.xlsx 说明表在 WPS/Excel 里开着
ls ../../raw/data/wechat/*.xls | wc -l    # 导出份数
```

- **表正被 WPS/Excel 打开时**：先让用户关闭再继续。脚本会自己拦这一步（检测到 `.~公众号文章数据分析表.xlsx` 就拒绝运行并提示）；**不要删锁文件绕过**——用户在办公软件里一保存，就会把脚本写入的整列结构/结论/样式覆盖回旧版（真发生过一次）。
- 数据源只有 `raw/data/wechat/*.xls` 一个；如果用户说"更新"但那里没有新文件，直接说明没有可导入的新数据，不要凭空造。

### 步骤 2：运行

```bash
cd tools/wechat-data && python3.12 import_wechat_export.py
```

脚本自己完成：解析 → 增量并入 sheet1 → 重算 sheet2 透视表 → 需要时扩表/挪动「填写说明」。

### 步骤 3：判读输出

| 输出 | 含义 / 动作 |
|---|---|
| `解析失败: …` + `未改动输出文件` | **停下报告**。说明哪份文件、缺什么指标或表头，怀疑后台导出改版。**不要**改用别的路径硬凑数据、不要手工填进表 |
| `表结构已迁移…` / `表头已修正…` | 正常的一次性结构升级 |
| `新文章 N 篇 / 刷新数据 N 篇 / 历史保留 N 篇` | 本次增量结果，N 篇都要汇报 |
| `＋新增` / `↻刷新` / `＝保留` | 逐条明细，汇报时把新增的标题列给用户 |
| `告警: …占比 > 100%` | 渠道去重差导致，该列已跳过，属已知现象 |
| 透视表行数 / 分组数 | 用于说明分析结果变化 |

### 步骤 4：汇报（说人话，别只贴日志）

1. **新增了哪几篇**：标题（截断即可）+ 发布日期 + 阅读人数。
2. **哪些篇目的数据被刷新**：列 → 旧值 → 新值（一般会有几篇，因为后台数字在增长）。
3. **结论列的读法（v2）**：`【定位】流量结构+轨道+最弱维度`、`【诊断】三个指标与**同层**水平对比`、`【动作】按轨道×短板`。分层是前提——算法型完读中位 20.7%、私域型 46.9%，跨层比必然误判。另一张 `流量结构透视` 给三层各自的中位表现与该层怎么用。若某组结论里的动作与数值不符（例如两项都高于全表却说传播弱），说明规则该调，报告给用户并改 `conclusion()` / `ACTIONS`。
4. **需要人工确认的**：
   - E/G 分类是我按标题规则推的，让用户抽查；**新文章若分类明显不对**，在脚本顶部 `TITLE_RULES` 加一行固化（`("标题关键词", "内容方向", "核心价值类型"),`），再重跑一次。
   - 打开率 >100% 的篇目（推荐流量远超群发送达人数，该列对这类文章不可解释）。
   - 没有用户画像、X/Y 为空、匹配度无法判定的篇目。
4. **不要**把整个 41 行明细表贴给用户，摘要即可。

### 步骤 5：边界

- **不提交 git**，除非用户明确要求（且遵守仓库规则：禁止 `git add .`、禁止在 main 上直接提交）。
- 不动人工列（D 字数 / E 内容方向 / F 人群匹配度 / G 核心价值类型 / P 跳出率）——脚本本身也不会覆盖。
- 不删 `raw/data/wechat/` 里的任何文件（删了表里那行也不会消失，这是刻意的"行永不删除"）。
- 不改模板的判定标准、不擅自动打开率口径——这些属于用户决策，有问题先报告。

## 关键事实（省得每次重新摸索）

| 项 | 值 |
|---|---|
| 脚本 | `tools/wechat-data/import_wechat_export.py`（python3.12；依赖 xlrd + openpyxl） |
| 数据源 | `raw/data/wechat/*.xls`（**唯一**投递口，文件名原样保留，含尾部空格和括号） |
| 产物 | `公众号文章数据分析表.xlsx`：sheet1 `文章数据记录`（A~AM 39 列六层；第二层含 `目标人群阅读量`（阅读×25-45岁占比，成绩单口径），第五层含 `46岁以上占比`（反向护栏，色阶绿→红）；第二层＝阅读人数/送达人数/公众号消息阅读人数/首次分享人数/订阅打开率/订阅分享率，第六层＝八个渠道占比（**按行染色**：每行一条色阶、白→深蓝，行内比出主力渠道），第四层＝点赞/在看/分享人数/分享率/分享产生的阅读人数/分享扩散系数/读后关注人数；第 6~49 行数据区，按发布日期倒序，关键指标列带红-黄-绿色阶）、sheet2 `方向×价值类型透视`（结论列分三行居左：【定位】/【诊断】/【动作】） |
| 母本 | `公众号文章数据分析模板.xlsx`（同目录）——仅首次生成分析表时用（`fresh` 分支：分析表不存在时从它复制，并抄它的数据行样式）。原本已丢失，2026-09-21 从 WPS 缓存副本找回 |
| 规则文档 | `数据提取与维护规则.md`（同目录） |
| 分类规则位置 | 脚本顶部 `TITLE_RULES` / `DIRECTION_RULES` / `VALUE_RULES` / `VALUE_BY_DIRECTION` |
| 公式缓存值 | 脚本保存后会往公式格注入缓存结果（`inject_cached_results`）——否则 WPS 重算前读不到数，色阶不着色、显示空白。输出里会打印注入了多少格 |
| 阈值常量 | `FEMALE_THRESHOLD=0.6`、`YOUNG_THRESHOLD=0.5`（三档匹配度）、透视表结论标准见 `verdict()` |
| 两种导出的写法差异 | 人数版给百分比、次数版给**绝对人数**（女 51/男 13）与不同年龄段（46-60/60岁以上）；脚本按合计归一化，别把人数当百分比 |
| 已知空白列 | D 字数（导出没有，只能人工填）、Q 微信收藏人数（仅人数版导出有）、Z/AA/AB + 匹配度（读者太少后台无画像） |
| 列口径 | 数值型公式由 `FORMULA_INPUTS` 的分子/分母列名自动生成（订阅打开率 L / 订阅分享率 M / 分享扩散系数 Y / 收藏率 S / 分享率 W / 涨粉转化率 AE）；`阅读次数`/旧`打开率`/`跳出率`已删；列位置由脚本 `LAYERS` 定义，每跑一次自动重铺表头 |
| 两种导出结构 | 人数版 / 次数版，脚本按表头取列自动兼容 |
