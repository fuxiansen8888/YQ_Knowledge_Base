# 原创写作（四层联动）

一句话：**写之前先把四层串一遍，不要凭印象下笔。**

为什么值得串：库里已经沉淀了 43 篇正文、43 篇的数据、29 条未写选题、5 份方法论文档。凭印象写等于把它们全扔掉——而且会反复写已经写过的立意。

## 四层各管什么

| 层 | 出什么 | 入口 |
|---|---|---|
| `知识/` | 方法论 | [[目标读者痛点地图]]（痛点维度 + 经历资产映射）、[[数据洞察与写作方向plan]]（两轴筛选 §4.2 / 题材池 §4.3 / 排期 §4.4 / 标题 §3.1 / 承接 §3.4）、[[自媒体文章起标题技巧]]、[[选题框架]]（单篇模板）、[[排版规则]] |
| `个人原创/` | 我的声音 + 查重 | `个人原创/索引.md` 表 A（数据面）/ 表 B（立意、结构、开头方式、标题句式、可复用的一句）；要看原文点表 A 的标题 |
| `原始素材/` | 现场与证据 | `数据/公众号/`（后台数据）、`评论/`（读者原话，引用**必须匿名**）、`对标/`（别人怎么写）、`待整理/`（新料）、`对话/` |
| `工具/` | 账本 | 分析表 sheet1（数据口径）、「选题库」sheet（哪些已写、哪些还空着） |

## 触发场景

- 「写一篇关于 X」「这个选题能写吗」「帮我想几个选题」
- 「这篇初稿帮我看看怎么收」「这个立意对不对」
- 「出几个标题」「标题怎么改」
- 「新素材 / 新数据来了，能写什么」「这个热点值得写吗」
- 「这篇发完了，复盘一下」

## 执行流程

### Phase 1 · 检索（不许跳）

四层并联，产出一张**素材卡**直接给用户看（不建文件）：

```
【素材卡】主题：X
事实     ：原始素材里有什么真实材料（数据 / 评论原话 / 事件）
痛点     ：[[目标读者痛点地图]] 里对应哪个维度、哪条经历资产
我写过吗 ：[[索引]] 表 B 查到的相近立意与句式，含那篇的数据
选题状态 ：[[选题框架]] 或「选题库」sheet 里有没有这条、标什么状态
轴 1 打开率潜力：高 / 中 / 低（能不能做成「数字 ＋ 具体事件 ＋ 反转」）
轴 2 精准度    ：高 / 中 / 低（是否指向 25-45 岁女性的处境）
结论     ：写 / 换切口写 / 不写（轴 2 低的一律不写）
```

**查重是这一步的重点。** 在 `个人原创/索引.md` 表 B 里搜主题词、近义词、经历关键词。命中相近立意时，明确说出「上次那个立意是 X，这次要给出什么新东西」——同题重写是这一层最常犯的错。

### Phase 2 · 立意（先给用户确认，再往下写）

按 [[选题框架]] 的模板走，字段一个不省：

1. **事实**——只有原始素材里有的东西，不许补
2. **立意**——指南针一句话（这一篇到底在主张什么）。库里的母题是「不是 A，而是 B」（见 [[索引]]），但 **B 必须是我真经历过、能写出场景的**；写不出场景就说明还不到能写的时候
3. **对方在问什么**——把对方的动机写准，不许写成「他想偷懒」
4. **框架表**——逐节：字数 / 写什么 / 状态
5. **三个 craft 注意**——具体的操作戒律（例：不贬低对方、不炫耀「我坚持了」、结尾不写「我选对了」）
6. **标题候选 3 个**——按 §3.1 出
7. **置顶评论触发句**

### Phase 3 · 落笔

- 初稿写进 `个人原创/草稿/`（题面沿用 Phase 2 的框架表；**不加 frontmatter**）
- 开头按 §3.4：前三段必须有具体场景或一句对话。[[索引]] 的统计同向支持（「身体细节场景」13 篇的打开率中位 4.61%，是「结论先行」的近两倍）
- 长文分节
- 结尾留系列钩子

### Phase 4 · 发布前检查

逐条对 [[排版规则]]，另外清一次粘贴痕迹：**整段被 `###` 包裹、转义反斜杠（`1\.5小时`、`\!\`）、行尾 `\~`**（§3.6）。

固定三件（§4.5）：文末关注理由（A/B/C 版按题材选）、评论区置顶、系列钩子。

### Phase 5 · 回填（闭环，别省）

一篇写完不算结束，这条链要走完：

1. 发表后把 `初稿_` + `定稿_` 两个文件从 `草稿/` 移进 `已发布/后续发表文章（含初稿定稿）/`——`定稿_` 就是发表版正文，不必等后台导出
2. 在 `个人原创/索引.md` 表 A 补一行（标题 / 日期 / 方向 / 价值 / 字数 / 阅读 / 打开率 / 完读 / 25-45 / 涨粉），表 B 补立意与手法
3. 后台导出的 `.xls` 丢进 `原始素材/数据/公众号/`，用 `gongzhonghao-data-update` skill 并入分析表
4. 在分析表「选题库」sheet 对应行回填「是否已写 / 对应文章标题 / 数据表现」
5. 新发现写回 `知识/`（痛点地图、数据洞察、标题模式……**改前先备份到 `备份/`**）
6. 记 `log.md`（只追加）

## 硬约束

1. **数据优先于印象。** 分析表与 `知识/` 里的结论冲突时，先报告冲突并登记 `待核实`，不要按一边悄悄写。现有两处在 [[索引]]：标题句式、分节与完读。
2. **不虚构。** 不引入我没有的经历、读者没说过的话、数据里没有的数字。评论引用必须匿名。
3. **不改我的文风、不替我表态。** 润色排版可以；替我把话说成另一个意思、替我署名或站队，不行。
4. **`个人原创/已发布/` 默认不改。** 确要改，先备份到 `备份/<YYYY-MM-DD>/个人原创/已发布/`。
5. **不给正文加 frontmatter**——YAML 会跟着正文一起被复制进公众号后台。
6. **不提交 git**，除非用户明确要求（且遵守仓库规则：禁 `git add .`、禁在 main 上直接提交）。

## 常见偏差

| 偏差 | 纠正 |
|---|---|
| 直接开写初稿，跳过 Phase 1 | 先出素材卡，包括「我写过吗」 |
| 立意写成「读者以为的」，不是「我实测的」 | 回到 Phase 2 第 2 条：写不出场景就还不能写 |
| 只查 `知识/`，忘了 `个人原创/索引.md` | 漏掉就等于放弃了自我查重，这一层的主要价值就在这里 |
| 一篇写完不更新索引和选题库 | 下次查重就失准，等于这次白写 |
